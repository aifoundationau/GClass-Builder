PART 2: HOW TOKENS WORK IN THIS APP
================================================================================

THE SHARED SYSTEM (unchanged; the main guide's PART 2 has the full detail)
  - One balance per person, users/{uid}.token_balance, shared by every app in
    ai-foundation-firebase. The same Google account is the same uid in every app,
    so tokens bought in any app add to one total and can be spent in any app.
  - Every change is a token_ledger entry, saved in the same atomic commit as the
    balance, with a key that stops it happening twice.
  - The price per token is set once, in the AI Foundation admin panel (Services &
    Pricing -> Tokens). USD $1 when blank. Australians pay the AUD price if set.
  - Buyers choose any whole number of tokens from 10 (+ and - move by 10) and pay
    with Stripe Checkout. The server works out the price; the browser only says
    how many tokens.
  - Only the two SuperAdmins can add tokens for free (Token Accounts).

THIS APP'S SHAPE
  This app is a React (Vite) front end, a Python API (run locally or in Docker)
  and a few Vercel functions in api/. The token kit is a Node/Express API, so:
  - On Vercel: api/token-api.js is one function running the kit's routes.
    vercel.json sends these addresses to it:
      /api/tokens and /api/tokens/*   balance, checkout, confirm, spend,
                                      accounts, grant
      /api/profile/sync               creates the shared profile on sign-in
      /api/exchange-rates/usd-aud     SuperAdmin only, optional
      /api/firebase/config            for public/tokens.html
  - Locally: npm run dev (dev-runner.mjs) starts three things:
      Python API ........ http://127.0.0.1:8000
      token API ......... http://127.0.0.1:8001  (server.js)
      the app (Vite) .... http://localhost:5173
    Vite sends the token addresses above to 8001 and every other /api address to
    Python (vite.config.js).
  - Docker: the image runs only the Python API, so it has no token API (PART 7).

ONE SIGN-IN
  The app keeps its own Firebase Google sign-in (src/firebase.js). The kit's
  public/firebase-client.js is not used inside the app. Instead
  src/services/tokenAuthBridge.js does its three jobs:
    1. adds the user's Firebase ID token to token API requests (only those; the
       app's other /api routes keep using the Classroom sign-in cookie)
    2. calls POST /api/profile/sync after each sign-in
    3. sets window.appAuthState and fires 'appAuthChanged', which
       public/tokens-ui.js listens for
  The Tokens tab's own "Sign in with Google" button uses the same sign-in.

THE TOKENS TAB
  src/components/TokensPanel.jsx holds the kit's Buy Tokens and Token Accounts
  sections from public/tokens.html, with every id unchanged. The first time the
  tab opens it loads tokens.css, token-pricing.js and then tokens-ui.js, and it
  stays on the page (hidden) after that, because tokens-ui.js connects to those
  elements only once. Token Accounts appears only when the server says the user
  is one of the two SuperAdmins.
  Stripe sends buyers back to /?tokens=success&session_id=... (or
  ?tokens=cancelled). The app opens the Tokens tab for those addresses, and
  tokens-ui.js confirms the payment.

PROFILES
  POST /api/profile/sync creates users/{uid} with 0 tokens on a person's first
  sign-in to any app. If the profile exists, it keeps the balance and role and
  adds 'gcoursebuilder' to the profile's apps list, so the profile records every
  app the person uses. The app's own sign-in only updates the person's name,
  photo and last sign-in on an existing profile: roles are this app's own (Role
  Permissions), and the Superadmin is the owner's Google account.

THE STANDALONE PAGE
  public/tokens.html (the kit's page, with the kit's own sign-in) also works at
  /tokens.html. Nothing links to it. The kit's tests use it, and it can serve as
  a direct "buy tokens" link.

COMMONJS MARKERS
  The app's package.json says "type": "module", but the kit is CommonJS. So
  lib/, public/, tests/ and scripts/ each have a small package.json with
  "type": "commonjs", and the kit files run unchanged. Vercel's bundle for
  api/token-api.js includes lib/package.json and public/package.json (checked
  with Vercel's tracer, @vercel/nft 1.11.0). public/package.json is also copied
  into the built site, which is harmless.

PART 5: SELLING THINGS FOR TOKENS IN THIS APP
================================================================================

Nothing is for sale yet, so no prices were invented. When something is:

SHOW THE PRICE WITH THE TOKEN ICON
  Use lucide-react's Coins icon (the same icon as the Tokens tab), small, next to
  the amount:
      import { Coins } from 'lucide-react';
      <span><Coins size={14} /> 50 tokens</span>

CHARGE ON THE SERVER
  Tokens are money: the server decides the price, never the browser. Add the paid
  route to api/token-api.js (it runs on Vercel, and locally through server.js):

      import auth from '../lib/auth.js';
      import tokenBalances from '../lib/token-balances.js';

      // Made on first use, so a bad APP_TAG can't crash the function at startup.
      // APP_TAG and APP_NAME are the constants at the top of api/token-api.js
      let tokenStore = null;
      function tokens() {
        if (!tokenStore) tokenStore = tokenBalances.createTokenStore({ appTag: APP_TAG, appName: APP_NAME });
        return tokenStore;
      }

      const TEMPLATE_PRICE_TOKENS = 50;

      app.post('/api/shop/templates/:id/buy', auth.attachUser, auth.requireAuth, async (req, res) => {
        try {
          const result = await tokens().spendTokens({
            uid: req.user.uid,
            tokens: TEMPLATE_PRICE_TOKENS,
            app: APP_TAG,
            // The purchase's own ID: sending it again never takes tokens twice
            reference: `template-${req.params.id}-${req.user.uid}`,
            description: `Template ${req.params.id}`
          });
          if (result.status === 'insufficient') {
            return res.status(409).json({ error: 'Not enough tokens.', balance: result.balance });
          }
          // 'spent' or 'already-spent': give the user what they paid for here
          res.json({ ok: true, balance: result.balance });
        } catch (e) {
          console.error('[Template purchase]', e);
          res.status(500).json({ error: 'Tokens could not be spent just now, and none were taken.' });
        }
      });

  Then send the new address to the token API:
    - vercel.json: a rewrite from /api/shop/:path* to /api/token-api, above the
      last rewrite.
    - vite.config.js: '/api/shop' to http://127.0.0.1:8001, above '/api'.
    - src/services/tokenAuthBridge.js: add shop to TOKEN_API, so the browser's
      request carries the ID token.
  References: up to 100 characters from A-Z a-z 0-9 _ . : -

WHERE THE USER CHOOSES THE AMOUNT (a tip, for example)
  The browser can call POST /api/tokens/spend with { tokens, app: 'gcoursebuilder',
  reference, description }. Answers: 200 { status: 'spent' | 'already-spent',
  spent, balance } or 409 { error: 'Not enough tokens.', balance }.

PYTHON FEATURES
  The Python API (course creation, the AI agent) uses the Classroom sign-in, not
  the Firebase ID token, and the kit has no Python version. To charge for a Python
  feature, take the tokens in a Node route as above first, or ask an agent to plan
  a server-to-server design. Never change token_balance from Python with a plain
  write.

PART 7: TROUBLESHOOTING
================================================================================

The main guide's PART 7 covers the token messages. For this app:

Tokens tab says "Tokens are not set up on this server yet (APP_TAG is missing)"
  APP_TAG is set but empty or not a valid tag, in .env or in Vercel. Delete it
  (the tag is built in), then restart npm run dev or redeploy.

Tokens tab: "Could not load your tokens: Sign-in required"
  The Firebase sign-in is missing. Sign out and in again.

Tokens tab shows "..." and its sign-in button does nothing
  The token scripts did not load. The browser console shows
  "[Tokens] Could not load ...". This happens in the Docker image (below).

Locally, token requests fail with HTTP 500, and the terminal shows "http proxy
error ... ECONNREFUSED 127.0.0.1:8001"
  The token API on port 8001 isn't running. npm run dev starts it; make sure
  nothing else is using port 8001.

"npm run dev": Vite stops with "EPERM ... node_modules\.vite\deps"
  Another program has Vite's cache folder open. This happened on 24 Oct 2026,
  after npm install changed the lockfile. Close other dev servers, then delete
  the node_modules\.vite folder and start again.

Docker
  The Docker image runs only the Python API, so the Tokens tab can't load there.
  To support Docker, the image needs Node, with server.js running beside the
  Python API and the token addresses sent to it. Ask an agent to plan it.

Live site: /api/tokens answers 404 or "Cannot GET /api/token-api"
  The rewrites in vercel.json aren't working, or api/token-api.js wasn't
  deployed. Check the deployment's Functions list in Vercel.

Live site: 500 FUNCTION_INVOCATION_FAILED on token addresses
  Run npm run check:startup. If it says "require is not defined in ES module
  scope", a CommonJS marker package.json is missing.

Paid, but no tokens
  Open the Tokens tab again while signed in: unpaid checkouts are checked again
  and credited.
